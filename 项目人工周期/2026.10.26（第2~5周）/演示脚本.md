> 建议：提前一天完整彩排一次，并录屏兜底。

## 二、演示流程（5 分钟）

### 0:00–0:30 开场

- 打开 PPT 封面，一句话："这是一个面向校园课程资源的格式转换服务，核心是把零散工具做成可插拔、可追溯的平台能力。"
- 切到用户端登录页。

### 0:30–1:00 登录与能力目录

- 用 `student_demo` 登录。
- 打开浏览器开发者工具 Network（可选），展示 `GET /api/formats` 返回的能力目录；口头说明"可选引擎缺失会标记 available=false"。
- 回到上传页。

### 1:00–2:00 上传与创建任务

- 拖拽 `demo-sample.srt` 到上传区。
- 指出识别结果：`ext=srt`，推荐目标包含 `vtt`。
- 目标格式选 `VTT`，参数保持默认。
- 点击"创建任务"。
- 说明：任务进入 Redis ZSet 队列，优先级 + FIFO。

### 2:00–2:40 状态流转

- 进入任务详情，观察状态：`QUEUED → CONVERTING → QC → SUCCESS`。
- 指出：每一步都有状态机校验；失败会自动重试（上限 3 次）。
- 成功后页面出现下载按钮与 `downloadToken`。

### 2:40–3:20 一次性下载令牌（加分点）

- 复制 `downloadToken`。
- 新开无痕窗口，访问：
  `http://localhost:8080/api/tasks/{id}/download?token={token}`
- 浏览器直接下载，文件首行为 `WEBVTT`。
- 再用同一 URL 访问一次，返回：
  `{"code":1006,"message":"下载令牌已使用或已失效"}`。
- 口头说明：令牌绑定用户与产物、10 分钟有效、Redis SETNX 一次性消费。

### 3:20–4:00 提交反馈

- 回到任务详情，点击"反馈"（或进入反馈中心）。
- 评分 5 星，分类"体验"，标题"演示反馈"，内容一句话。
- 提交后进入"我的反馈"，展示状态 `PENDING`。

### 4:00–4:40 管理端回复

- 切到管理端（`admin_demo`）。
- 打开"反馈管理"，展示统计卡与筛选。
- 找到刚才的反馈，点击"回复"，填写"感谢反馈，已记录"，状态改为 `RESOLVED`。
- 回到用户端刷新"我的反馈"，展示管理员回复与状态变化。

### 4:40–5:00 收尾

- 切回 PPT 总结页。
- 一句话："可插拔、可验证、可演进。以上是本次结项汇报，欢迎提问。"

## 三、演示失败预案

| 故障 | 现场处理 |
|---|---|
| Docker 未启动/端口占用 | 直接播放预录视频，说明"环境已提前验证，这里用录屏展示完整链路" |
| 引擎转换失败 | 改用 SRT→VTT（纯 Java，不依赖外部工具）；仍失败则播放录屏 |
| 网络不可用 | 本地环境演示；AI 切规则模式（`CAMPUS_AI_PROVIDER=rule`） |
| 管理端登录失败 | 用 SYS_ADMIN 账号同时演示用户端与管理端 |
| 下载令牌报 401 | 令牌默认 10 分钟过期，重新进入任务详情获取新令牌 |
| 反馈列表为空 | 确认提交时未勾选匿名且使用同一账号；刷新页面 |

## 四、演示话术要点

- 不要说"我们做了很多功能"，要说"我们把转换做成了可插拔的平台能力"。
- 每个操作都对应一个设计点：上传→校验、创建→模板、进度→状态机、下载→令牌、反馈→闭环。
- 主动暴露边界："CAJ/DjVu/OCR 是可选引擎，未安装时能力目录会标记不可用，但不会影响主链路。"
